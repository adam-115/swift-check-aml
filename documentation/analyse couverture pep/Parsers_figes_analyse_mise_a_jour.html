Parsers figés : ceux qui publient des données fixes écrites en interne

11 novembre 2026. Analyse refaite : code des 283 plugins (branche courante) et base de l'application (swift_check_2, lecture seule). Est « figé » un parser dont la liste de personnes publiée vient du JAR du plugin, pas d'une lecture de la source à l'exécution.

Résultat. 61 parsers sont figés : 58 avec une liste de personnes embarquée dans le plugin et aucun accès réseau, et 3 dont la liste est écrite dans le code Java. S'y ajoutent 7 parsers qui lisent le réseau mais retombent sur une liste statique en cas d'échec, et 1 qui lit des actes en direct à partir d'une liste d'identifiants écrite en dur. Trois présidents publiés sont périmés (Pologne, Roumanie, Grèce).

1. Les quatre catégories

CatégorieParsersDéfinition et risque
A. Liste embarquée, sans réseau58Le parser lit un fichier seed/*.json dans le JAR. Aucune requête vers la source. Les données ne changent qu'avec une nouvelle version du plugin.
B. Liste codée en dur dans le Java3Les noms sont des constantes du code. Le réseau n'intervient que pour télécharger une page comme pièce justificative, pas pour établir la liste publiée.
C. Secours statique7La source est lue d'abord ; si la lecture échoue, une liste ou une page embarquée est publiée sans que la publication le signale.
D. Liste d'actes codée en dur1Les actes officiels sont lus en direct, mais la liste des actes à lire est fixe : une nomination postérieure n'est pas vue avant une modification du code.

  3. Ne pas exécuter les parsers grecs figés en production tant que leurs listes ne sont pas relues contre une pièce (Diavgeia, journal officiel) ; ils sont à 0 exécution, c'est le bon moment.
  4. Date d'expiration de 90 jours dans les listes embarquées : le parser échoue clairement au-delà ; même contrôle pour les listes codées en dur.
  5. Remplacer les listes figées par une lecture réelle, en commençant par le niveau 1 (chef de l'État, gouvernement, parlement, hautes juridictions, banque centrale) et par la Pologne, la Roumanie, le Portugal, l'Italie, les Pays-Bas, l'Espagne, la Grèce.
  6. Supprimer ou signaler les secours statiques (catégories C et D) ; automatiser la détection de nouvelles nominations pour es_pep_judiciary.
  7. Contrôle automatique : un test de construction qui refuse tout plugin publiant une liste de personnes sans lecture externe, et une colonne « Origine des données » dans l'écran des parsers.

7. Limites

  • L'analyse du code est automatique (présence de lecture réseau, de ressources embarquées, de noms en dur) ; des cas limites ont été vérifiés à la main pour les modules signalés, pas pour les 283.
  • Les trois présidents périmés sont établis à partir du contenu des listes et de ma connaissance des changements de titulaire ; les sites officiels n'ont pas pu être relus pour confirmation (anti-robot).
  • La base lue est celle de l'application locale au moment de l'analyse.
